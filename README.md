# Jabulile Mashibini — Developer Portfolio

Personal portfolio website of **Jabulile Mashibini** — Azure-certified software engineering
professional and technical facilitator, targeting junior roles in **DevOps, Cloud, Software
Engineering, and Full-Stack Development**.

The site is laid out like a transit map: one line for things built, one for work and study,
one for certifications.

**Live:**

| Host | URL |
|:--|:--|
| GitHub Pages | [jabulile1704.github.io](https://jabulile1704.github.io/) |
| Azure Static Web Apps | [proud-dune-0e00d6e10.3.azurestaticapps.net](https://proud-dune-0e00d6e10.3.azurestaticapps.net) |

Both deploy from `main` on every push, from the same build.

## Tech Stack

- **React 19** + **Vite 6** — component-based SPA
- **CSS custom properties** — light and dark themes, no CSS framework
- **Inline SVG** — the interactive transit map in `src/components/TransitMap.jsx`
- **GitHub Actions** — CI/CD to both hosts
- **Azure Static Web Apps** (Free plan) and **GitHub Pages** — hosting

All content (bio, projects, career, certifications, tools) lives in
[`src/data.js`](src/data.js), so the site can be updated without touching component code.

Station positions on the map are set at the top of `TransitMap.jsx` and are kept in sync by
hand with the map in the [GitHub profile README](https://github.com/Jabulile1704/Jabulile1704),
which is generated by `scripts/build-map.mjs` in that repo. Changing a station means editing
both.

## Run Locally

```bash
npm install

npm run build    # production build → dist/
npm run preview  # serve the production build locally
```

## Deployment

Every push to `main` runs two workflows, each building with Node 22 and `npm run build`:

- **GitHub Pages** publishes `dist/` to the `gh-pages` branch.
- **Azure Static Web Apps** uploads `dist/` with `skip_app_build: true`, so the Node version
  and build command are pinned here rather than chosen by Azure's build service.

### A note on the base path

Vite bakes asset paths into `index.html` at build time via its `base` option, and getting it
wrong produces a blank page whose only symptom is 404s in the console.

`vite.config.js` reads the base from `BASE_PATH`, defaulting to `/`. This repo is the
`<username>.github.io` **user site** and Azure serves from a domain root, so neither sets it
and both get `/`. `BASE_PATH` stays configurable only as an escape hatch for a host that
serves from a subdirectory.

`public/staticwebapp.config.json` is copied into `dist/` by Vite, which puts it at the root of
what Azure serves. It sets SPA fallback routing, the CV's MIME type, two security headers and
long-lived caching for content-hashed assets. It is inert on GitHub Pages.

See [`docs/AZURE_DEPLOYMENT.md`](docs/AZURE_DEPLOYMENT.md) for the full Azure setup, including
the region restrictions on Azure for Students and the `build` vs `dist` failure to watch for.
